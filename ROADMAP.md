# Daydock roadmap

Daydock is intentionally small. This roadmap records likely directions, not promises or deadlines. New features should preserve the daily-first workflow, plain Markdown storage, and low planning overhead described in the README.

## Current focus

- Make the early desktop release dependable on Windows, macOS, and Linux.
- Improve onboarding without adding setup complexity.
- Strengthen notebook safety, conflict handling, and recovery messages.
- Refine keyboard navigation and accessibility.
- Collect real-world feedback about the daily, weekly, and planning flows.

## Ideas under consideration

- Export tools, including PDF export
- More complete keyboard and command navigation
- Better management of files in `Assets/`
- Optional packaging for distribution channels such as the Arch User Repository
- Signed release builds when the project can support the required certificates

## Deliberate non-goals

Daydock is not currently trying to become:

- A calendar or time-blocking system
- A project management suite
- A database of tagged and categorized tasks
- A social productivity platform
- A service that requires an account or hosted storage

Ideas and contributions are welcome. For substantial changes, please open an issue before implementation so the problem and its fit with Daydock's direction can be discussed.
